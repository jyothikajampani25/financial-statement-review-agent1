1. Purpose of this document

This BRD states the business problem, who is served, what is in and out of scope, and what the solution must do.

It is the agreed requirement baseline. Design and build come after this document.

2. Business problem

Financial statements (Balance Sheet and Profit & Loss) must be reviewed for mathematical accuracy, year-on-year change, internal consistency, and clear review comments.

Manual review is slow. Totals can be wrong, prior-year links can be missed, and explanations are often written without a clear trail of evidence.

The business need is an AI-powered review agent that checks the numbers, compares years, flags inconsistencies, and writes review observations with supporting evidence from the statement itself.

3. Business objective

Provide a review service over company financial statements so that a reviewer can:

  • Validate that line totals and subtotals add up correctly
  • Compare current year vs prior year and see material variances
  • Spot internal inconsistencies (for example Balance Sheet identity, P&L roll-forward)
  • Receive short review observations with the source line / figure as evidence
  • Export or view a structured review pack for sign-off discussion

4. Stakeholders

Financial reviewer / analyst

Reviews Balance Sheet and P&L before management or audit discussion.

Needs fast checks, clear variance flags, and evidence-backed comments — not a black-box score.

Finance lead / reviewer sign-off

Owns the review quality.

Needs a short pack: what passed, what failed, what changed YoY, and what the agent observed.

5. Scope

In scope

  • Balance Sheet and Profit & Loss for one company at a time
  • Current year + at least one prior year
  • Math checks on totals and subtotals
  • Year-on-year variance with thresholds
  • Internal consistency checks
  • AI review observations with supporting evidence
  • Sample / dummy statements (or public Kaggle-style data)
  • A simple review UI for upload, run, and results
  • API access so other tools can call the same review
  • Notifications on complete / critical fail; health alert if down
  • Run trace and simple observation feedback

Out of scope

  • Full statutory audit opinion
  • Tax filing or compliance submission
  • Live ERP / bank integration in v1
  • Cash flow statement (unless data already present)
  • Multi-entity consolidation
  • Investment advice or stock tips

9. Business requirements

ID Requirement Priority
BR-01The agent shall accept Balance Sheet and P&L data for a company with current and prior year figures.Must
BR-02The agent shall validate mathematical accuracy of totals and subtotals and report pass / fail with the lines used.Must
BR-03The agent shall compare year-on-year performance and highlight variances above a defined threshold.Must
BR-04The agent shall check internal consistency (at minimum Balance Sheet identity: Assets = Liabilities + Equity).Must
BR-05The agent shall generate review observations that cite supporting evidence (line name, year, amount, rule result).Must
BR-06Generated commentary shall not invent numbers that are not present in the statement or rule output.Must
BR-07The reviewer shall see a clear summary: checks passed, findings, material variances, and observations.Must
BR-08The reviewer shall be notified when a review finishes and when a critical finding (math or consistency fail) is raised.Should
BR-09The service shall be reachable by other systems through a standard API (not UI-only), so it can sit in finance tools or chat channels later.Should
BR-10If the review service is unhealthy, operations shall receive an automatic alert (for example email) with enough detail to act.Should
BR-11Every review run shall leave a trace (who, when, company, result) and allow simple reviewer feedback on an observation (useful / not useful).Should

10. Assumptions and constraints

TypeStatement
AssumptionInput can be sample / dummy Balance Sheet and P&L, or public company statement data (for example Kaggle-style datasets).
AssumptionLine names can be mapped to a small standard chart of accounts for checks.
Constraintv1 is single-company review, not consolidation.
ConstraintThe agent assists review; it does not replace a licensed auditor’s opinion.
ConstraintNumeric truth comes from rules on the statement data. GenAI only explains those results.

11. Acceptance criteria

The requirement is met when all of the following are true on the sample dataset.

IDCriterion
AC-01A deliberately broken total is detected as a math fail, with the expected vs actual amounts shown.
AC-02A material YoY change (above threshold) appears in the variance list with both years’ values.
AC-03A Balance Sheet that does not balance is flagged as a consistency fail.
AC-04Each review observation shows the evidence (line / amounts / check id) used to write it.
AC-05A clean sample pack shows mostly passes and still produces a short YoY commentary where variance exists.
AC-06A critical fail triggers a notification path (demo: log + optional email) that names the company, run id, and check id.
AC-07A health endpoint reports down when the API cannot serve reviews; an alert can be demonstrated from that signal.
AC-08A review pack can be fetched by run id via API without opening the UI.
